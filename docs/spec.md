# Контракт `out/graph.json`

Ядро анализа (`pipeline/`) и интерфейс (`web/`) связаны **только** через файл
`out/graph.json`: пайплайн его пишет, браузер загружает одним запросом по адресу
`/out/graph.json`, `ask.py` строит по нему граф в памяти для ответов на вопросы.
Интерфейс ничего не пересчитывает по сырым данным, кроме симуляции изъятия узлов.

## Обязательные CSV-выгрузки (схема ТЗ)

| Файл | Строк | Колонки ТЗ | Наши дополнительные колонки |
|---|---|---|---|
| `out/nodes_roles.csv` | 2248 | `gid` (int64), `role`, `role_score`, `cluster_id`, `priority_score`, `evidence` | `rule_id` и признаки, на которых построены правила (степени, обороты, `pass_through`, `terminal_status`, `terminal_p`, временные флаги, `mutual_pair`, `in_cycle`, координаты) |
| `out/clusters.csv` | 72 | `cluster_id`, `n_nodes`, `n_seed`, `sum_kzt_internal`, `top_gids`, `hypothesis` | состав по ролям, оборот наружу и внутрь, геометрия клина на схеме |
| `out/top_nodes.csv` | 30 | `rank`, `gid`, `role`, `priority_score`, `why` | `cluster_id`, `role_score`, `rule_id` |

## Структура `graph.json`

| Ключ | Содержимое |
|---|---|
| `meta` | размеры графа, оборот, период, время прогона, распределения ролей, правил и статусов, счётчики паттернов, результаты устойчивости (`robustness`), параметры раскладки (`layout`) |
| `roles` | словарь ролей: подпись и пояснение для интерфейса |
| `nodes` | все 2248 узлов, включая 19 seed без рёбер: поля ТЗ, `rule_id`, признаки, `why` (обоснование приоритета), координаты `x`, `y` в [0, 1] |
| `edges` | 3119 рёбер: `src`, `dst`, `sum_kzt`, `n_tx`, `depth` |
| `clusters` | 72 кластера: поля `clusters.csv` |
| `top_nodes` | 30 узлов: поля `top_nodes.csv` |

## Правила контракта

- **`gid` в `graph.json` — всегда строка.** Идентификаторы 18-значные и превышают
  2^53, `JSON.parse` в браузере исказил бы их. Строками передаются `nodes[].gid`,
  `edges[].src`, `edges[].dst`, `clusters[].top_gids[]`, `top_nodes[].gid`
  (`meta.gid_is_string = true`). В CSV `gid` остаётся `int64`, как требует ТЗ.
- `pass_through`, `terminal_p`, `hold_days_median`, `fast_out_share` могут быть `null`
  (нет входящих, нет рёбер, нет исходящих транзакций) — интерфейс это учитывает.
  `NaN` в файл не попадает: документ очищается при записи.
- У кластера `-1` (seed без рёбер) нет геометрии клина — поля `angle_start`,
  `angle_end`, `r_inner`, `r_outer` равны `null`.
- `meta.stub` в выгрузке пайплайна всегда `false`; если флаг поднят, интерфейс
  предупреждает, что данные предварительные, а `/api/health` сообщает его значение.
- Поля только добавляются, существующие не переименовываются и не меняют тип.
