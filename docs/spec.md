# Контракт между дорожками

Кейс: «Граф денег» — восстановление финансовой структуры организованной группы
по транзакционной сети. Пользователь — AML-аналитик банка второго уровня.

Ядро и интерфейс разрабатываются параллельно и связаны **только** через файл
`out/graph.json`. Никто не читает чужие исходники и не правит чужие файлы.

## Области файлов

| Дорожка | Файлы | Кто |
|---|---|---|
| Ядро анализа | `pipeline/**`, пишет `out/**` | Claude |
| Интерфейс | `web/**`, читает `out/graph.json` | Codex |
| Сервер, деплой, README, коммиты | `server.py`, `README.md`, `docs/**` | оркестратор |

Исходные данные организаторов — `case/data/*.parquet`, только на чтение.
Стартовый код организаторов — `case/starter/`, трогать не надо, он справочный.

## Запуск

```bash
.venv/bin/python -m pipeline.run --data case/data --out out
.venv/bin/python server.py            # отдаёт web/ и out/ на 127.0.0.1:3300
```

## Обязательные выгрузки (схема из ТЗ, менять нельзя)

`out/nodes_roles.csv` — ровно 2248 строк, по строке на каждый gid:

| Колонка | Тип | Смысл |
|---|---|---|
| `gid` | int64 | идентификатор клиента |
| `role` | str | одна из: consolidator, transit, distributor, terminal, coordinator, peripheral |
| `role_score` | float | уверенность в роли, 0–1 |
| `cluster_id` | int | номер кластера |
| `priority_score` | float | приоритет для аналитика, 0–1 |
| `evidence` | str | почему присвоена роль, с числами, до 200 символов, человекочитаемо |

`out/clusters.csv` — по строке на кластер: `cluster_id`, `n_nodes`, `n_seed`,
`sum_kzt_internal`, `top_gids`, `hypothesis`.

`out/top_nodes.csv` — не менее 20 строк: `rank`, `gid`, `role`, `priority_score`, `why`.

Правила контракта:

- `nodes` содержит **все** 2248 узлов, включая 19 seed без единого ребра;
- `pass_through` может быть `null` — у узлов без входящих; интерфейс обязан это пережить;
- поля только добавляются, существующие не переименовываются и не меняют тип;
- пока ядро не готово, в `out/graph.json` лежит заглушка с `meta.stub: true` —
  интерфейс обязан показывать предупреждение, когда флаг поднят.

## Что показываем жюри (сквозной сценарий)

1. Аналитик открывает ссылку — видит схему сети, роли подсвечены, кластеры разделены.
2. Ищет по gid — узел подсвечивается, открывается досье: роль, обоснование, потоки, связи.
3. Открывает топ-лист приоритетов — читает обоснование по каждому узлу.
4. Двигает ползунок «изъять топ-N узлов» — видит, на сколько фрагментов распалась сеть
   и какая доля оборота отрезана.
5. Задаёт вопрос словами — получает ответ по графу со ссылками на узлы.

Пункты 1–3 обязательны по ТЗ. Пункты 4–5 — наш нестандартный ход, делаются после того,
как обязательная часть проходится целиком.

## Ограничения, которые нельзя нарушить

- никакого хардкода списков gid под «правильный ответ» — только расчёт;
- у каждой роли формальное правило с порогом, задокументированное в README;
- выводы формулируются как гипотезы для проверки, а не как утверждение о виновности;
- полный пересчёт от сырых parquet до выгрузок — не более 5 минут;
- внешних источников данных нет, атрибуты клиентов не выдумываются.
